# Upstream Sync And Backend Policy

This fork should stay close to [BasedHardware/Omi](https://github.com/BasedHardware/Omi) while preserving Adam's local product changes. Use this runbook when pulling upstream changes into `adamlsneed/omi`.

## Remotes

Expected remotes:

```bash
git remote -v
```

```text
origin    https://github.com/adamlsneed/omi.git
upstream  https://github.com/BasedHardware/Omi.git
```

Add upstream if it is missing:

```bash
git remote add upstream https://github.com/BasedHardware/Omi.git
git fetch origin
git fetch upstream
```

## Sync Strategy

1. Start from the fork branch that should receive upstream changes, usually `main`.
2. Create a safety branch before merging.
3. Merge upstream with a real merge commit so fork history remains visible.
4. Resolve conflicts by preserving fork-only features and taking upstream service, protocol, and backend compatibility changes unless there is a documented local reason not to.
5. Verify no conflict markers remain.
6. Run targeted checks for every touched area.
7. Commit locally, then push only when Adam is ready.

Commands:

```bash
git checkout main
git fetch origin
git fetch upstream
git branch backup/main-before-upstream-sync-$(date +%Y%m%d)
git merge --no-ff upstream/main
```

## Conflict Resolution Rules

Use these defaults during conflict resolution:

| Area | Default choice | Reason |
| --- | --- | --- |
| Hosted backend URLs and auth | Keep BasedHardware production hosted config | Adam's paid subscription depends on hosted Omi services |
| Desktop Rust backend API/paywall/BYOK code | Prefer upstream unless fork behavior is explicit | Upstream owns current subscription and service contracts |
| Python backend (`backend/`) | Always take upstream exactly: after the merge, `git checkout upstream/main -- backend/`, delete fork-only backend files, commit with `--no-verify` so the format hook cannot reintroduce drift | The fork never modifies `backend/`; it runs against BasedHardware's hosted backend |
| Mobile task, reminders, and local UX features | Preserve fork additions | These are Adam's fork-specific product changes |
| L10n ARB and generated Dart files | Start from upstream and add fork keys back | Avoid losing upstream translations while keeping local UI strings |
| Firmware protocol, BLE, storage, and sync | Prefer upstream | Devices need current BasedHardware protocol behavior |
| Fork firmware additions (idea-capture) | Preserve, and renumber on collision | Button states `6`/`7` + haptic modes `8`/`9` are fork-only; an upstream merge may reuse those numeric slots without a conflict marker — see [Fork Firmware Reservations](#fork-firmware-reservations-idea-capture) |
| Docs and local setup notes | Combine | Keep upstream docs and add fork-specific guardrails |

## Fork Firmware Reservations (idea-capture)

The fork carries a firmware-driven **idea-capture** feature (shipped on `main`, PR #51, fw `3.0.21`). It extends two existing BLE characteristics with fork-only numeric values plus a runtime flag. Upstream does not know these slots are taken, so a firmware merge can silently reuse the same numbers for an unrelated feature. **These collisions do not produce conflict markers** — the numbers compile fine and the device just does the wrong thing. Check them by hand after any firmware merge.

Reserved values (firmware constants under `omi/firmware/omi/src/`):

| Slot | Value | Firmware constant | App constant |
| --- | --- | --- | --- |
| Button characteristic state | `6` | `HOLD_ENTER` (`lib/core/button.c`) | `buttonState == 6` (`app/lib/providers/capture_provider.dart`) |
| Button characteristic state | `7` | `HOLD_EXIT` (`lib/core/button.c`) | `buttonState == 7` (`app/lib/providers/capture_provider.dart`) |
| Haptic characteristic mode | `8` | `HAPTIC_MODE_IDEA_CAPTURE_ON` (`haptic.c`) | `_hapticModeIdeaCaptureOn` (`app/lib/services/devices/omi_connection.dart`) |
| Haptic characteristic mode | `9` | `HAPTIC_MODE_IDEA_CAPTURE_OFF` (`haptic.c`) | `_hapticModeIdeaCaptureOff` (`app/lib/services/devices/omi_connection.dart`) |

Upstream currently uses button states `1`–`5` (single-tap / double-tap / long-tap / press / release) and haptic modes `0`–`7`. The fork's values sit just above those ranges.

Rules on a firmware merge:

- **New control commands stay MODE/STATE VALUES on the existing characteristics** — never add a new GATT characteristic for them. iOS caches the GATT table across a DFU, so a new characteristic silently fails to appear until the BLE cache is cleared.
- If upstream adds a **new button state** at `6`/`7` or a **new haptic mode** at `8`/`9`, the fork keeps its feature and **renumbers the idea-capture value upward** to the next free slot, then updates the firmware constant **and** its matching app constant in the same commit. The two sides must agree or the gesture breaks.
- Confirm the numbers still line up before flashing (grep both sides — see [Files To Check After A Merge](#files-to-check-after-a-merge)).

Preserve these fork-only firmware additions on every merge (grep anchor `idea-capture` marks each hook):

- `lib/core/button.c` — `HOLD_ENTER`/`HOLD_EXIT`, the 1s `HOLD_PRESS_TIME` gesture, `notify_hold()`.
- `haptic.c` — modes `8`/`9`, the solid-green LED + buzz cases.
- `main.c` — the `set_led_state()` idea-capture green branch and its precedence over mute/charging/connected.
- `settings.c` / `lib/core/settings.h` — the runtime `idea_capture_active` flag (app-driven, not persisted; resets to inactive on reboot).
- `VERSION` + `omi.conf` (`CONFIG_BT_DIS_FW_REV_STR`, currently `3.0.21`) — keep the fork's version **higher** than upstream, or OTA rejects the build as a rollback.

## Backend Invariant

Adam's normal development and testing path must stay on BasedHardware's hosted backend:

```bash
API_BASE_URL=https://api.omi.me/
USE_WEB_AUTH=true
USE_AUTH_CUSTOM_TOKEN=true
OMI_PYTHON_API_URL=https://api.omi.me
OMI_DESKTOP_API_URL=https://desktop-backend-hhibjajaja-uc.a.run.app
```

Practical rules:

- Prefer `desktop/run.sh --yolo` for desktop app testing.
- Local desktop deploys always target "Omi Dev" (`/Applications/Omi Dev.app`, bundle id `com.omi.desktop-dev`), installing on top of the existing app. Never set `OMI_APP_NAME` to deploy under another name.
- Keep mobile `.env` and `.dev.env` pointed at `https://api.omi.me/` for subscription-backed testing.
- Do not replace hosted endpoints with personal tunnels, local URLs, or private service deployments in committed files.
- Use local Python or Rust backend URLs only inside ignored environment files and only for backend-specific debugging.
- If an upstream merge introduces a new default endpoint, review it before committing.

```bash

```

Conflict markers:

```bash
rg -n "^(<<<<<<<|=======|>>>>>>>)" .
```

Fork firmware reservations (idea-capture), after any firmware merge — confirm button states `6`/`7` and haptic modes `8`/`9` are still unique on both the firmware and app sides (see [Fork Firmware Reservations](#fork-firmware-reservations-idea-capture)):

```bash
rg -n "idea-capture" omi/firmware/omi/src app/lib/providers/capture_provider.dart app/lib/services/devices
rg -n "HOLD_ENTER|HOLD_EXIT|HAPTIC_MODE_IDEA_CAPTURE" omi/firmware/omi/src
```

L10n consistency:

```bash
cd app
flutter gen-l10n
```

Generated JSON and ARB sanity:

```bash
python3 -m json.tool desktop/CHANGELOG.json >/tmp/omi-changelog.json
```

## Verification Checklist

Run the checks that match the touched areas:

| Touched area | Minimum verification |
| --- | --- |
| Desktop Swift | `cd desktop && xcrun swift build -c debug --package-path Desktop` |
| Desktop Rust backend | `cd desktop/Backend-Rust && cargo check` |
| Mobile Dart/Flutter | `cd app && flutter test` |
| Mobile l10n | `cd app && flutter gen-l10n` |
| Backend Python | `cd backend && ./test-preflight.sh && ./test.sh` |
| Docs only | Link scan or at least `rg` checks for stale paths |
| Merge conflict resolution | `git diff --check` and conflict marker scan |

If a tool is missing locally, record that explicitly in the final notes instead of implying the check passed.
