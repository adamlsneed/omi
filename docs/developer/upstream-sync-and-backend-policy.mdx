# Upstream Sync And Backend Policy

This fork should stay close to [BasedHardware/Omi](https://github.com/BasedHardware/Omi) while preserving Adam's local product changes. Use this runbook when pulling upstream changes into `adamlsneed/omi`.

## Remotes

Expected remotes:

```bash
git remote -v
```

```text
origin    https://github.com/adamlsneed/omi.git
upstream  https://github.com/BasedHardware/Omi.git
```

Add upstream if it is missing:

```bash
git remote add upstream https://github.com/BasedHardware/Omi.git
git fetch origin
git fetch upstream
```

## Sync Strategy

1. Start from the fork branch that should receive upstream changes, usually `main`.
2. Create a safety branch before merging.
3. Merge upstream with a real merge commit so fork history remains visible.
4. Resolve conflicts by preserving fork-only features and taking upstream service, protocol, and backend compatibility changes unless there is a documented local reason not to.
5. Verify no conflict markers remain.
6. Run targeted checks for every touched area.
7. Commit locally, then push only when Adam is ready.

Commands:

```bash
git checkout main
git fetch origin
git fetch upstream
git branch backup/main-before-upstream-sync-$(date +%Y%m%d)
git merge --no-ff upstream/main
```

## Conflict Resolution Rules

Use these defaults during conflict resolution:

| Area | Default choice | Reason |
| --- | --- | --- |
| Hosted backend URLs and auth | Keep BasedHardware production hosted config | Adam's paid subscription depends on hosted Omi services |
| Desktop Rust backend API/paywall/BYOK code | Prefer upstream unless fork behavior is explicit | Upstream owns current subscription and service contracts |
| Python backend routes, payments, subscription plans | Prefer upstream unless editing a fork feature | Hosted backend compatibility matters more than local drift |
| Mobile task, reminders, and local UX features | Preserve fork additions | These are Adam's fork-specific product changes |
| L10n ARB and generated Dart files | Start from upstream and add fork keys back | Avoid losing upstream translations while keeping local UI strings |
| Firmware protocol, BLE, storage, and sync | Prefer upstream | Devices need current BasedHardware protocol behavior |
| Docs and local setup notes | Combine | Keep upstream docs and add fork-specific guardrails |

## Backend Invariant

Adam's normal development and testing path must stay on BasedHardware's hosted backend:

```bash
API_BASE_URL=https://api.omi.me/
USE_WEB_AUTH=true
USE_AUTH_CUSTOM_TOKEN=true
OMI_PYTHON_API_URL=https://api.omi.me
OMI_DESKTOP_API_URL=https://desktop-backend-hhibjajaja-uc.a.run.app
```

Practical rules:

- Prefer `desktop/run.sh --yolo` for desktop app testing.
- Keep mobile `.env` and `.dev.env` pointed at `https://api.omi.me/` for subscription-backed testing.
- Do not replace hosted endpoints with personal tunnels, local URLs, or private service deployments in committed files.
- Use local Python or Rust backend URLs only inside ignored environment files and only for backend-specific debugging.
- If an upstream merge introduces a new default endpoint, review it before committing.

## Files To Check After A Merge

Backend and auth defaults:

```bash
rg -n "api\\.omi\\.me|api\\.omiapi\\.com|OMI_PYTHON_API_URL|OMI_DESKTOP_API_URL|API_BASE_URL" app desktop AGENTS.md README.md docs
```

Conflict markers:

```bash
rg -n "^(<<<<<<<|=======|>>>>>>>)" .
```

L10n consistency:

```bash
cd app
flutter gen-l10n
```

Generated JSON and ARB sanity:

```bash
python3 -m json.tool desktop/CHANGELOG.json >/tmp/omi-changelog.json
```

## Verification Checklist

Run the checks that match the touched areas:

| Touched area | Minimum verification |
| --- | --- |
| Desktop Swift | `cd desktop && xcrun swift build -c debug --package-path Desktop` |
| Desktop Rust backend | `cd desktop/Backend-Rust && cargo check` |
| Mobile Dart/Flutter | `cd app && flutter test` |
| Mobile l10n | `cd app && flutter gen-l10n` |
| Backend Python | `cd backend && ./test-preflight.sh && ./test.sh` |
| Docs only | Link scan or at least `rg` checks for stale paths |
| Merge conflict resolution | `git diff --check` and conflict marker scan |

If a tool is missing locally, record that explicitly in the final notes instead of implying the check passed.
